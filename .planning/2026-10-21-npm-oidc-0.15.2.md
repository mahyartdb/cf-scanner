# Plan — restore the npm channel via OIDC, ship 0.15.2

Goal: `npm install -g @qmahyar/cf-scanner` works again, and no long-lived npm
credential exists anywhere in the pipeline.

Context: 0.15.1 published to GitHub but its `npm-publish` job aborted with
`ENEEDAUTH` (no `NPM_TOKEN`), leaving npm at 0.15.0 — whose `install.js`
points at the non-existent `qmahyar/cf-scanner` and 404s. Classic npm tokens
were removed in November 2025 and bypass-2FA token publishing is removed in
January 2027, so the fix is OIDC trusted publishing, not a new secret.

## Steps

- [x] 1. `release.yml` npm-publish job: Node 24, no `NODE_AUTH_TOKEN`, no
      `registry-url`, npm-version floor guard. Accept: `git grep NODE_AUTH_TOKEN
      .github/` returns nothing.
- [x] 2. Version triple -> 0.15.2 (`Cargo.toml`, `npm/cf-scanner/package.json`,
      `npm/cf-scanner/install.js` `RELEASE_TAG`). Accept: the CI `version-parity`
      shell snippet passes locally.
- [x] 3. CHANGELOG entry for 0.15.2 covering both the pipeline change and the
      0.15.0 -> 0.15.2 jump npm users see. Accept: entry present under `[0.15.2]`.
- [x] 4. Gates: `cargo build/test/clippy/fmt --locked` green, `Cargo.lock`
      carries 0.15.2. Accept: all exit 0; lock version matches Cargo.toml.
- [x] 5. Manual, user-side: configure the npm trusted publisher
      (`mahyartdb/cf-scanner`, workflow `release.yml`) within the 2-day
      validation window before tagging.
- [x] 6. Commit, then tag `v0.15.2` and push — remote side effects, needs
      explicit approval. Accept: Release workflow runs plan -> gate ->
      cross-check -> build -> host -> npm-publish, all green.
      Done: run 39543382090, every job success, 14 release assets.
- [x] 7. Verify `npm view @qmahyar/cf-scanner version` = 0.15.2 and a clean
      `npm i @qmahyar/cf-scanner` install runs `cf-scanner --version`.
      Done: `latest` = 0.15.2 (registry propagation took ~3.5 min), clean
      install in a scratch dir prints `cf-scanner 0.15.2`, and
      `npm audit signatures` reports a verified registry signature and a
      verified attestation (SLSA provenance v1).

## Rollback

If the OIDC publish fails, the release is already on GitHub; re-running the
job is safe (same tag, same artifacts). If npm never accepts OIDC, fall back
to a granular token for one release and revisit before January 2027.
